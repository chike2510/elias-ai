# Elias Browser Extension

This Manifest V3 companion lets a user capture the active page or a selected passage and create a research task in Elias. It also provides the first Elias computer-use bridge: a paired browser can claim durable, approval-gated navigation, click, typing, scroll, screenshot, and extraction actions generated by an Elias task. The main Elias web app remains the execution authority: models, connectors, source verification, approvals, artifacts, and task state stay server-side.

## Local installation

1. Open `chrome://extensions` in Chrome or Chromium.
2. Enable **Developer mode**.
3. Choose **Load unpacked**.
4. Select this `extension/` directory.
5. Open the extension popup or side panel on a public page.
6. For passive research, enter an instruction and choose **Capture page and send**.
7. For computer-use tasks, open the side panel, enter the outcome, and choose **Start browser task**. Keep **Browser control** enabled while Elias works. The side panel will show live task progress and approval requests.

The extension calls `https://elias-ai-chi.vercel.app/api/extension/capture` for passive capture, or `/api/extension/browser/sessions` for a computer-use session. It polls `/api/tasks/:taskId/events` for task progress and `/api/extension/browser/actions/:sessionId` for queued browser actions. Completed browser observations are returned to Elias and can resume the task.

## Security model

The content script reads only an explicit user selection. The popup and side panel read the active page only after the user clicks capture. Password fields, hidden inputs, and page credentials are not collected. Captured page text is labeled as user-provided context and must be independently verified by Elias before being treated as evidence.

The extension does not contain model, GitHub, Vercel, or search credentials. Click and typing actions are always approval-gated by Elias before they are released to the extension. External writes must remain behind Elias approval steps. The bridge is limited to the active tab, requires the user to keep browser control enabled, and does not collect password fields or hidden inputs. Pairing tokens are short-lived signed bearer tokens and must be treated as credentials.

## Shared Goal Progress Card

The extension uses the task record and event snapshot returned by Elias. The web app and extension therefore display the same task ID, plan steps, status, approvals, errors, and terminal result. Closing the extension does not cancel a task.

## Files

- `manifest.json`: Manifest V3 permissions and entry points.
- `background.js`: Context menus, capture orchestration, notifications, and task polling.
- `content.js`: Explicit selection capture.
- `popup.html`, `popup.css`, `popup.js`: Quick capture popup.
- `sidepanel.html`, `sidepanel.css`, `sidepanel.js`: Persistent task monitor.
